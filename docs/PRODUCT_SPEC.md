# CreaseLog 제품 기획 및 구현 범위

## 제품 목적

레슨 기록 → 선수 과제 → 수행 기록 → 다음 레슨 확인 → 월간 성장 리포트의 연결을 만든다. 코치는 2–3분 안에 핵심을 기록하고, 선수는 지금 할 한 가지를 이해하며, 부모는 공개가 승인된 성장 과정만 확인한다.

초기 파일럿은 코치 1명, 선수 5명과 연결된 부모가 4주간 사용한다. 선수 프로필은 로그인 계정 없이 만들 수 있고, 한 부모는 여러 선수와 연결될 수 있다. 장기적으로 조직과 여러 코치를 지원한다.

## 역할

- **코치**: 연결된 선수 관리, 목표, 레슨/과제/영상, 다음 확인, 승인형 리포트, 별도 비공개 메모
- **선수**: 자신의 공개 기록, 과제 완료, 자기평가/메모, 성장 기록과 영상
- **부모**: 연결된 자녀 선택, 공개 기록/수행 상태/승인된 리포트, 동의와 연결 관리

클라이언트의 역할 선택은 권한이 아니다. 서버의 조직 membership과 선수 access를 모두 만족해야 한다. 코치 메모는 공개 피드백과 별도 테이블 및 별도 조회 경로로 둔다.

## 화면 구조

- 로그인/초대: 로그인, 일회성 초대 확인, 역할·선수 확인, 보호자 동의, 만료 오류
- 코치: 선수 목록, 최근/작성 중 레슨, 확인할 과제, 새 기록
- 선수 상세: 프로필, 시즌/현재 목표, 타임라인, 과제, 영상, 리포트
- 레슨 작성: 필수 필드, 태그, 영상, 비공개 메모, 초안/미리보기/공개, 저장 상태
- 선수 홈: 핵심 과제 하나, 잘한 점, 영상, 완료, 자기평가, 다음 확인
- 부모 홈: 자녀 선택, 목표, 레슨 요약, 좋아진 점, 수행 상태, 승인 리포트
- 설정: 연결/동의, 정책, 문의, 내보내기, 삭제, 로그아웃

## 상태 규칙

- 레슨: `draft` → `published` → `archived`. draft는 작성 코치에게만 보인다.
- 과제: `planned` → `active` → `athlete_done` → `coach_verified`.
- 두 상태는 독립적이다. 선수 완료가 코치 확인으로 자동 변경되지 않는다.
- 공개 레슨 수정 시 `updated_at`을 보여주고, 이를 근거로 승인된 리포트는 `needs_review`가 된다.
- 근거가 없으면 “기록이 부족합니다”로 표시하며 자동 향상 판정을 하지 않는다.

## MVP / 이후 / 제외

**MVP:** 로그인과 연결, 프로필/목표, 레슨, 과제/자기평가, 비공개 영상, 타임라인, 승인형 월간 리포트, 연결/삭제 설정.

**이후:** 음성 초안, 코치 승인 전 AI 요약, 영상 후보 추출, 푸시, 오프라인 동기화. 개인정보의 AI 전송은 별도 설명과 동의 전에는 활성화하지 않는다.

**제외:** 공개 순위/비교/커뮤니티, 채팅, 예약·결제, 자동 기술 평가.

## 단계별 현황 (2026-09-15)

| 단계 | 상태 | 실제 범위 |
|---|---|---|
| 1. 구조·기술·문서 | 완료 | Expo 프로젝트, 문서, 가상 데이터, 실행 안내 |
| 2. 핵심 UI | 부분 완료 | 5개 요청 화면과 역할 전환. 설정/빈 상태 상세는 후속 |
| 3. 인증·연결·저장·권한 | 설계만 완료 | SQL/RLS 초안. 서버와 앱은 연결되지 않음 |
| 4. 수행·평가·리포트 | UI 일부 | 가상 표시만 있으며 저장/승인 없음 |
| 5. 비공개 영상 | 미구현 | 정책과 데이터 모델만 작성 |
| 6. 사용성·iOS/TestFlight | 준비 문서 | 실제 빌드/서명/배포 안 됨 |

## 파일럿 측정

- 기록 작성 시간 중앙값 ≤ 3분
- 실제 레슨 대비 작성률 ≥ 80%
- 공개 72시간 내 선수 열람률 ≥ 70%
- 기한 내 완료 체크율 ≥ 60%
- 부모 월간 리포트 열람률 ≥ 80%

이는 예측이 아니라 소규모 검증 목표이며 인터뷰와 함께 판단한다.
